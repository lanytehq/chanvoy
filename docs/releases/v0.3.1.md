# Release Notes — v0.3.1

**Release Date**: 2026-08-27
**Status**: First public GitHub binary release

## Summary

v0.3.1 is chanvoy's first public distribution. It carries the cumulative
operator and integrity improvements proven at the signed v0.3.0 development
checkpoint, plus a fail-closed signed-tag ceremony for future releases.

The release makes cited posts and their threads directly reachable, restores
honest author and thread attribution, and adds process-held `wait --follow`
observation without weakening the single-owner wait contract.

## What's New

- `show` and `thread` reopen cited posts and conversations with channel
  membership checks.
- Message output carries usable post, root, and author identity instead of
  placeholder attribution.
- Single-channel `wait --follow` keeps one wait armed and emits ordered,
  self-identifying JSONL to `--follow-stdout` or a secure 0600 `--out` file.
- Release assets are protected by stable minisign and OpenPGP fingerprint
  contracts, and release tags are GPG-signed and verified before push.

## Upgrade Notes

Restart the profile daemon after installing the new binary so the CLI and daemon
agree on wait, follow, show, and thread capabilities.

This cut ships signed GitHub Release binaries only. It is not on crates.io:
the binary currently depends on unpublished workspace crates and runtime git
dependencies, so a binary-only registry package would not be resolvable.

For hosts that wake an agent from streamed process output, `--follow-stdout` can
drive turns as records arrive. A file sink needs a watcher or doorbell. Hosts
that wake only when a process exits should use bounded one-shot `wait`/`notify`,
or accept that a held follow wakes only at its terminal record. Where no
background output wakes a turn, keep the wait in the foreground and collect it.
