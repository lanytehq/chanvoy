# Release Notes — v0.2.0

**Release Date**: 2026-05-02
**Status**: Local-mode polish bundle (PER-014 + PER-019 + PER-015 Phase 1)

## Summary

The local-mode polish push is functionally complete. v0.2.0 bundles
**PER-014** (sandbox-aware daemon startup), **PER-019** (cross-team
channel resolution), and **PER-015 Phase 1** (diagnostic harness for
the daemon-startup / namespace-drift failure family).

This was the first chanvoy release published with the Mattermost-
adoption-ready surface — sandbox-friendly startup, cross-team channel
resolution, cursor isolation per `<team>/<channel>` pair, and a
forensic harness for diagnosing daemon-startup failures.

## What's New

### Sandbox-aware daemon startup (PER-014)

`chanvoy auto-setup` works end-to-end under sandbox restrictions
(Codex agents, macOS sandboxd, Docker without `--network`, OSS
sandbox setups). The detached daemon no longer needs network access
at startup — identity validation moved into the parent CLI, and the
validated identity is handed off to the daemon child via a
per-profile bootstrap-state file with a one-shot nonce.

Three sandbox failure modes are now first-class operator paths:
- **Path 0** (network-only sandbox): chanvoy already handles it; one
  approval prompt at first `auto-setup`.
- **Path 1** (socket path unwritable): redirect via
  `CHANVOY_RUNTIME_DIR=$HOME/.chanvoy-runtime`.
- **Path 2** (socket unreachable from sandbox): foreground daemon in
  parent shell via `chanvoy --profile <name> daemon serve`.
- **Path 3** (both paths blocked): escalate to supervisor; chanvoy
  doesn't negotiate sandbox permissions.

### Cross-team channel resolution (PER-019)

Channel-name resolution finds channels across every team the bot is
a member of, not just the profile's primary team. Closes the
silent-404 cross-team posting gap.

```bash
# Bare name resolves via γ hybrid (primary first, fallback across teams)
chanvoy read leadership --since 1h

# Explicit team override — wins over the primary chain
chanvoy read org-3leaps/leadership --since 1h
chanvoy read leadership --team org-3leaps --since 1h
```

Ambiguous names (the same channel name on multiple teams) refuse
with a diagnostic listing the candidates. Cursors are independent
per `<team>/<channel>` pair, so reading `org-3leaps/leadership`
does not advance your cursor for `org-lanytehq/leadership` even if
both exist.

Pre-PER-019 cursor records migrate automatically on daemon startup;
ambiguous historical names quarantine rather than silently bind to
the wrong team.

### Diagnostic harness (PER-015 Phase 1)

`scripts/per015-diag.sh` ships as a forensic tool for diagnosing
daemon-startup / namespace-drift failures. PER-015 itself was
investigated and **scope-collapsed to done** — no Phase 2
implementation needed; the post-PER-014/PER-019 baseline resolves
the originally-observed failure.

## Breaking Changes

None. v0.2.0 is fully backward-compatible with v0.1.x.

## Migration Notes

Profile and attention-state files from v0.1.x load forward via
`#[serde(default)]` migration. Pre-PER-019 cursor records with bare
channel names migrate to qualified `<team>/<channel>` keys at daemon
startup; ambiguous historical names land in a quarantine list rather
than silently binding.

To upgrade: `make install`, then `chanvoy daemon stop` and
`chanvoy auto-setup` to cycle any running daemon onto the new
binary.
