## What's New

### First public release — signing, build, publish pipeline

**PER-031** lands `.github/workflows/release.yml`. On `git push origin vX.Y.Z` the workflow:

1. Validates that the `VERSION` file matches the pushed tag
2. Builds 3 cross-platform binaries on a strict matrix:
   - `chanvoy-vX.Y.Z-linux-x86_64` on `ubuntu-22.04`
   - `chanvoy-vX.Y.Z-linux-aarch64` on `ubuntu-latest-arm64-s` (Arm-Limited managed self-hosted runner; native build)
   - `chanvoy-vX.Y.Z-macos-aarch64` on `macos-14`
3. Generates `checksums.txt` (SHA-256)
4. Creates a draft GitHub release with the binaries + checksums + release notes attached

Workflow-hardening posture is strict: tag-only trigger (no `pull_request_target`, no `workflow_dispatch`), job-level least privilege (workflow default `contents: read`; only the aggregate job overrides to `contents: write`), single source-inspectable `GH_TOKEN: ${{ github.token }}` on the aggregate job, no signing material referenced anywhere.

**PER-030** lands the local-execution surface that consumes that draft. After the GHA workflow produces the draft, the maintainer runs:

```bash
make release-download   # fetch draft assets
make release-checksums  # regenerate checksums.txt locally
make release-export-keys
make release-sign       # minisign per-binary + GPG over checksums.txt
make release-verify     # signatures + key-fingerprint check
make release-upload     # gates on release-verify; attaches signed artifacts
make release-undraft    # flips draft → published
```

Signing keys are local-only — they never touch CI. `make release-preflight` is the pre-tag readiness gate (clean tree, version sync, no conflicting tag/release, tooling + signing keys present); it does not inspect a draft because none exists yet at that point in the flow.

Public verification commands and stable key fingerprints for external adopters live in `RELEASE_CHECKLIST.md` §11 (public-readable at the repo root).

### Reproducible release builds

**PER-031** also tightens `make build-release` to `cargo build --release --locked --package chanvoy`. The `--locked` contract lives in the Makefile rather than as a workflow-only bypass, so local `make build-release` and CI `make build-release` resolve dependencies identically.

### `reqwest` 0.12 → 0.13 + advisory clearance

**PER-033** bumps the workspace `reqwest` pin from `=0.12.15` to `=0.13.3`. The bump drops the transitively-pulled `rustls-pemfile` 2.2.0 crate, clearing **RUSTSEC-2025-0134** at the dep-graph level. The previous `deny.toml` ignore for that advisory is removed; `advisories.ignore` is now empty.

TLS composition delta (acknowledged trust-surface change; reviewed and accepted by secrev + devrev):

- TLS engine — **rustls (unchanged)**
- Crypto provider — `ring` → **`aws-lc-rs`** (FIPS-eligible AWS-LC fork)
- Cert verification — bundled `webpki-roots` → **`rustls-platform-verifier`** (OS trust store)

This is **not** a switch to native-tls / OpenSSL. `default-features = false` retained; `features = ["json", "rustls"]`. `webpki-roots` is still in the workspace via `tokio-tungstenite` (WebSocket TLS path; unchanged).

`aws-lc-rs` adds native-code build requirements (CMake / C compiler) — the v0.2.2 release matrix runners have these on their build environments.

### Release-cycle hygiene

**PER-032** adds the `make release-smoke` target — a live-Mattermost URL-shape smoke against a disposable test channel, invoked between `make release-prep` and `make release-preflight` in the canonical sequence. A failed smoke halts the release cycle **before** any tag is created, draft release exists, or signed artifact is produced. The failure surface is "no release tag yet" — never "signed release that doesn't work."

PER-032 also includes a `read --since` test and the endpoint manifest groundwork that PER-028 + PER-029 build on.

### `pin` / `unpin` write verbs

**PER-034** adds `chanvoy pin <channel> <post-id>` and `chanvoy unpin <channel> <post-id>` — pin/unpin a post under the bot's identity, retiring the manual Mattermost-API curl workflow. Channel resolution uses the same cross-team γ hybrid resolver as `react` / `pinned` (accepts `<team>/<channel>` and `--team`). Both verbs are idempotent (re-pinning a pinned post exits 0 with `was_already_pinned: true`; symmetric for unpin) and cursor-neutral. A `403` from Mattermost is normalized into a verb-specific diagnostic naming the missing channel-admin permission rather than a raw API error.

### Profile identity-reduction policy (parallel-stream operators)

**PER-035** adds an optional profile-level **reduction policy** so a stream-suffixed engagement bot (e.g. `agent-dataeng-blue-s2`) automatically posts under its bare **family** identity (`agent-dataeng-blue`) for any channel outside its engagement team — eliminating the per-call `--profile` discipline and the `auto-setup` active-profile hijack risk when one family bot runs multiple parallel sessions.

- A `[reduce]` table on the profile (`reduce.use_profile = "<family>"`); the scope marker is the existing `team_name`.
- Channel **resolution** and pre-write **verification** run on the calling (stream) identity; only the terminal write reduces, and only when the resolved channel's team ≠ the profile's `team_name`. In-team writes and `whoami` keep the stream identity. Applies uniformly to `post`, threaded replies, `react`, `unreact`, `pin`, `unpin`.
- Distinct from PER-019's channel-team `fallback`; the audit log names both provenances independently (`[team-fallback]`, `[identity-reduce]`).
- New surfaces: `chanvoy auto-setup --reduce-profile <family>` registers the policy; `chanvoy profile show <name>` reports a profile's identity + policy.
- The reduce target's token is **whoami-validated at daemon start** against the expected family bot; a mismatch (e.g. a family profile sharing an `env_name` with the stream) or a missing target fails closed — the daemon refuses to start rather than post stream identity under a false attribution.

### `--message-file` + stdin input for message-writing verbs

**PER-036** adds a `--message-file <path>` flag and the `-` stdin convention to every message-writing verb — `post`, `dm send`, the legacy `dm <user> <message>` form, and `notify` — eliminating the `$(cat file.md)` shell-substitution workaround for multi-line bodies. Exactly one source per call (positional / `--message-file` / `-`); the body is sent verbatim (trailing newline preserved). CLI-only — no daemon-side change. Over-length is deferred to Mattermost (its `Posts.MaxPostSize` is server-configurable); chanvoy normalizes a length rejection to name the received character count.

### ADR-0016 safe agent-critical file-read conformance

**PER-036A** brings chanvoy's named file reads into the [ADR-0016](https://github.com/lanytehq/lanyte-crucible/blob/main/docs/decisions/adr-0016-agent-critical-file-input-symlink-policy.md) baseline (PER-036's `--message-file` reader was the reference implementation). On a shared dev machine a planted symlink at a named path could redirect a read to any operator-readable file and exfiltrate it into a channel; chanvoy now **fails closed**. A new `chanvoy-core::safe_read` module provides three trust tiers:

- **caller-named** (`--message-file`): refuse a symlinked final component (`symlink_metadata`, no follow), refuse non-regular files (FIFO/socket/device/directory), bounded read (4 MiB).
- **credential** (`--env-file`): the above plus a 64 KiB cap and (on Unix) refusal of group/world-accessible files; diagnostics never print token contents.
- **tool-owned** (persisted profiles, `active_profile`, attention state, bootstrap handoff): follows a symlink to a regular file (dotfile/seclusor layouts) but refuses non-regular targets, bounds the read, and verifies the containing directory is operator-owned and not group/world-writable before trusting it.

Scope is the ADR portable floor (final-component symlinks); intermediate-directory symlinks and the metadata→open TOCTOU race are documented out-of-scope (`O_NOFOLLOW`+`fstat` is the named Unix hardening upgrade).

## Upgrade Notes

- **Installation**: `make install` continues to build from source. v0.2.2 is the first release shipping signed binaries — see `RELEASE_CHECKLIST.md` §11 for the external-adopter verification commands once the published release is available.
- **CLI surface — additive**: v0.2.2 adds the `pin` / `unpin` verbs (PER-034); the `--message-file <path>` flag and `-` stdin convention on `post` / `dm send` / `dm` / `notify` (PER-036); and `auto-setup --reduce-profile <name>` + `profile show <name>` (PER-035). All existing verbs and arguments are unchanged — the positional `<message>` form still works, so existing scripts are unaffected. PER-029 stripped internal brief-IDs from `--help` text (cosmetic).
- **File-input handling (ADR-0016, PER-036A)**: a **symlinked** `--message-file` or `--env-file` path is now refused (pass the real/resolved path); `--env-file` credential files must be owner-only (`chmod 600` — group/world-accessible files are refused on Unix) and under 64 KiB. This is a behavior change for anyone who passed symlinked or loose-permission file inputs. See the operator guide's "Agent-Critical File Reads (ADR-0016)" section.
- **Reduction policy (PER-035)**: opt-in per profile and off by default — profiles without a `[reduce]` block behave exactly as in v0.2.1. A reduce-configured profile requires its family profile to have a distinct token env (the daemon validates this at start).
- **TLS implementation**: reqwest now uses `aws-lc-rs` + `rustls-platform-verifier` for HTTP TLS. Operator-managed Mattermost is expected to use a CA-trusted certificate; if your environment uses a private CA, it must be present in the OS trust store (a change from v0.2.1, which used the bundled Mozilla webpki-roots bundle).
- **MSRV**: unchanged at Rust 1.89.0.
