# Release Notes — v0.2.1

**Release Date**: 2026-05-08
**Status**: Session-start ergonomics + conversation-shape + discovery
+ cross-team admin completion + onboarding doc surface

## Summary

v0.2.1 is the first release where chanvoy feels complete to a new
agent walking into a long-running channel. The four-line session-
start ritual — pinned context, bounded recent history, ack baseline,
next-session check — works end-to-end. Multi-reviewer review cycles
get cleaner via threaded replies + reactions. Channel discovery
(search + traffic-aware listing) lands. Every chanvoy verb that
touches a channel is now cross-team aware.

PER-026 ships the major onboarding doc surface expansion alongside
the dev work — agent-first 30-minute getting-started, symptom-keyed
troubleshooting, runtime-model architecture.

Five briefs landed in this release:

- **PER-023** — session-start ergonomics (4 primitives + general `--limit`)
- **PER-024** — conversation shape (threading + reactions)
- **PER-025** — discovery (search + channels enriched)
- **Cross-team `channel create --team`** — admin-verb completion
- **PER-026** — onboarding doc surface

Plus one v0.2.1-blocker bugfix (the canonical MM `pinned` endpoint),
caught during PER-026 dogfooding.

## What's New

### Session-start ergonomics (PER-023)

The four-line session-start ritual:

```bash
chanvoy pinned <channel>                  # canonical context (pure read)
chanvoy read <channel> --since-bootstrap  # 50 most-recent posts
chanvoy ack <channel>                     # mark current-latest read
# next session:
chanvoy check <channel>                   # exit 0 if new posts
```

Four primitives, one PR:

- **`chanvoy pinned <channel>`** fetches just the channel's pinned
  posts via MM `GET /channels/{id}/pinned`. Pure read; no cursor
  side effects. Resolves cross-team via the γ hybrid resolver.
- **`chanvoy read --since-bootstrap`** returns the bounded
  most-recent-N posts (default N=50; override with `--limit N`).
  Replaces the legacy `--since 999999` hack.
- **General `--limit N`** on `chanvoy read` composes with any
  read mode (`--since` / `--after` / `--since-last-mine` /
  `--since-bootstrap`). Hard cap on the result set; PER-023 does
  NOT add full-window pagination semantics. Bare
  `read --limit N` (no read-mode flag) is rejected with a
  diagnostic suggesting `--since-bootstrap --limit N`.
- **`chanvoy read --advance`** advances the attention cursor to
  the latest post **returned** by this read (mode-independent
  rule). No-op when zero posts returned.
- **`chanvoy ack <channel>`** advances the cursor to the
  channel's current latest post id without surfacing content.
  No-op success on empty channels.

**Time-window suffix parsing** lands on every time-window flag:
`read --since`, `notifications --since`, `wait --timeout`, and
`search --since` (PER-025). Accepts `30s`/`5m`/`4h`/`2d`. Bare
integer preserves today's per-flag default (minutes for all
three). Uppercase `M` and `mo` are loud-failed with a diagnostic
to avoid month/minute ambiguity.

Resolution is per-flag and not uniform; the suffix grammar is
the same across flags, but downstream precision depends on the
underlying API surface:

- `read --since` and `wait --timeout` are **second-precise**
  (hits MM with millisecond precision for read; local timer for
  wait).
- `notifications --since` is **minute-rounded** — the MM
  notifications surface is minute-keyed, so sub-minute suffixes
  round up to the next whole minute.
- `search --since` is **date-granular** — chanvoy composes the
  flag value as the MM-native `after:<YYYY-MM-DD>` operator;
  sub-day precision isn't supported by MM's search-after surface.
  Operators expecting hour-or-finer search windows should plan
  on date-level narrowing.

### Conversation shape (PER-024)

Threaded replies and emoji reactions for cleaner multi-reviewer
review cycles. Observed during PER-019's review cycle (11 reviewer
findings + ~30% acks-as-text-posts in a 30-post channel) — PER-024
makes the same review cycle ship with reactions instead of acks
and threaded replies for actual fix-commit follow-ups.

```bash
# Threaded reply (nests under parent post)
chanvoy post <channel> "fixed in 54661a7" --reply-to <parent-id>

# Emoji reactions — cleaner than text "lgtm" replies
chanvoy react <channel> <post-id> +1
chanvoy react <channel> <post-id> heavy_check_mark
chanvoy unreact <channel> <post-id> +1
```

Channel context is **positional and required** on `react`/`unreact`
even though Mattermost can key reactions by post-id alone — Slack's
reactions API requires the channel-id tuple, so chanvoy's CLI is
shaped portable from day one.

Reactions are **idempotent**: re-react with the same emoji is a
no-op success; unreact-when-not-reacted is a no-op success (chanvoy
normalizes MM's 404 path so the operator contract is "this
reaction does not exist after the call returns"). Reactions are
**cursor-neutral** — they never advance attention cursors.

`PostReceipt` JSON shape is **additive**: non-threaded posts return
`{ "id": "<post_id>" }` byte-identical to v0.2.0; threaded posts
add `parent_id`. Existing JSON consumers see no change.

### Discovery (PER-025)

Channel-scoped search and traffic-aware channels listing.

```bash
# Find posts in a specific channel (cross-channel deferred from v1)
chanvoy search per-019 "parent_pid validation"
chanvoy search per-019 "parent_pid" --from entarch --since 7d --limit 5

# Cross-team scope
chanvoy search org-3leaps/leadership "deadline"
```

**Inline operator conflicts** refuse with a diagnostic naming the
chanvoy-owned scope: `in:` vs the channel arg, `from:` vs `--from`,
`before:`/`after:` vs `--since`. Non-conflicting MM operators pass
through verbatim. **Quoted-region-aware**: `"in: the brief"` is
searchable text, not an operator conflict.

Channels listing now surfaces a `last_active` column:

```
=== org-lanytehq ===
  org-lanytehq/bravo-team    Bravo Team    O    2h ago
  org-lanytehq/per-019       PER-019       O    3d ago
  org-lanytehq/quiet         Quiet         O    —
```

`chanvoy channels --sort active` sorts within each team group by
recency; `—` (or `null` in `--json`) for missing-activity channels
sorts last. PER-019 grouping is preserved — there's no flattening
across teams (deferred to a future `--flatten` decision if friction
surfaces).

`channels --json` adds `last_post_at` as i64 Unix epoch ms;
missing-activity is **required** to be `last_post_at: null`
(deterministic shape; never absent, never 0). The
`--primary-team --json` legacy path preserves the pre-PER-025 JSON
field set exactly (no `last_post_at` added).

### Cross-team `channel create --team`

Closes the last cross-team admin-verb gap. Every chanvoy verb that
touches a channel is now cross-team aware.

```bash
# Default — lands on the profile's primary team (legacy)
chanvoy channel create ops-discussions "Ops Discussions"

# Alt-team override
chanvoy channel create ops-discussions "Ops Discussions" --team org-3leaps
```

The `--team` override resolves through the bot's `/users/me/teams`
membership cache (with one self-healing force-refresh on no-match)
before posting; refuses with `NotAMemberOfTeam` diagnostic if the
bot is not a member of the requested team — matching the PER-019 γ
resolver's enforcement posture.

### Bugfix: `chanvoy pinned` endpoint URL

PER-023 originally shipped `chanvoy pinned` calling
`/channels/{id}/pinned_posts`; the canonical Mattermost v4
endpoint is `/channels/{id}/pinned` (no `_posts` suffix). Live
request returned 404. Wiremock test mocked the same wrong URL so
it didn't catch the live divergence — wiremock-vs-real-API drift
class. Caught by prodmktg dogfooding during PER-026; one-line fix
at `crates/chanvoy-core/src/lib.rs` plus three wiremock matcher
updates.

### Build & release-prep tooling

New release-cycle gate via `make release-prep` runs `pr-final` +
license compliance + vulnerability scan + CycloneDX SBOM
generation. Individual targets — `make sbom`, `make security-scan`,
`make license-check` — available for dev-loop use.

Goneat presence is required by the targets; they fail with a
clear install hint (`sfetch --repo fulmenhq/goneat`) when goneat
isn't on `PATH`. Defensible failure mode for a release gate
(letting a misconfigured environment ship un-scanned releases
would be the worse trade). New `.goneat/dependencies.yaml`
policy file with explicit permissive-license allow-list (MIT /
Apache-2.0 / BSD / ISC / Unicode-3.0 / Zlib / CC0-1.0 /
CDLA-Permissive-2.0); hard-refuse on copyleft. Symmetric
`deny.toml` for cargo-deny.

`rustls-webpki` bumped 0.103.11 → 0.103.13 to clear three
RUSTSEC advisories (RUSTSEC-2026-0098 / 0099 / 0104 — CRL parsing
+ name-constraint handling).

SBOM artifact generated by `make sbom` / `make release-prep` under
`sbom/chanvoy-vX.Y.Z.cdx.json` (CycloneDX JSON via Syft, 294
packages). The `sbom/` directory is gitignored — SBOMs are
dev-loop artifacts (per seclusor / ipcprims convention).
Release-cycle SBOMs may be attached to the corresponding GitHub
release as a downloadable asset by the operator cutting the tag.

## Breaking Changes

None. v0.2.1 is fully backward-compatible with v0.2.0.

## Migration Notes

**To upgrade**: `make install`, then `chanvoy daemon stop` and
`chanvoy auto-setup` to cycle any running daemon onto the new
binary. Profile and attention-state files from v0.2.0 load forward
unchanged. No protocol-level wire-format change.

**Deployment-time CLI/daemon version skew** is handled gracefully:
new CLI calling an old daemon falls back to approximate semantics
(legacy minute-resolution time fields populated alongside the new
seconds-resolution fields); old CLI calling a new daemon works
unchanged via the legacy fields.
