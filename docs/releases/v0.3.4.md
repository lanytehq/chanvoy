# Release Notes — v0.3.4

**Release Date**: 2026-11-08
**Status**: Signed GitHub Release binaries

## Summary

v0.3.4 activates native v1 daemon lifecycle management (`daemon start`,
`daemon stop`, `daemon restart`, and `auto-setup`) and adds read-only
`native_runtime` sandbox and capability diagnostics to `chanvoy doctor`.

Managed daemons now publish a descriptor-pinned v1 runtime record under the
native lifecycle authority, hold an inherited lifetime lease, and coordinate
graceful retirement over `runtime_retire_v1`. Retirement refuses with `Busy`
whenever active wait, follow-stream, or RPC obligations exist rather than
interrupting active waits, confirms whole-process exit and kernel listener
absence before unlinking the socket, and writes an `Exited` tombstone before
any successor epoch starts.

`chanvoy doctor` now surfaces a read-only `native_runtime` block
(`qualification: false`, `socket_access`, `process_inventory`, `listener_table`,
and optional `guidance`) so operators and sandboxed agent sessions can
distinguish filesystem or kernel-table permission denials (`denied`) from
ordinary daemon absence (`absent`) without mutating state or altering
`doctor` exit codes.

## What's New

- **Native v1 daemon lifecycle and `daemon restart`**:
  - Descriptor-pinned runtime records (`~/.chanvoy/lifecycle/records/<namespace-hex>.json`),
    namespace operation locks, inherited lifetime leases, and readiness handoff
    pipes bind each managed daemon epoch to its verified native process and
    control socket.
  - Two-pass native account process inventory and kernel Unix domain socket
    listener-table observation are implemented for macOS and Linux without
    external process tools (exercised end-to-end in the macOS disposable-home
    lifecycle fixture and covered by Linux unit and protocol tests).
  - For v1-managed daemons, `chanvoy --profile <name> daemon restart` retires
    the owned predecessor over `runtime_retire_v1`, verifies whole-process exit
    and listener absence, reaps the socket under the namespace lock, writes an
    `Exited` tombstone, and launches a fresh successor epoch.
  - For v1-managed daemons, active wait, follow-stream, or RPC work causes
    managed retirement to refuse with `Busy` while preserving the running
    daemon (never force-killing active waits).
  - Pre-v0.3.4 daemons without a v1 runtime record on disk use the verified
    legacy stop fallback during `daemon stop` and `daemon restart`; that legacy
    fallback does not refuse with `Busy` and terminates active waits after its
    shutdown grace window.
- **`chanvoy doctor` `native_runtime` diagnostics**:
  - Reports `qualification: false`, `socket_access` (`reachable` | `absent` |
    `denied` | `unreachable`), `process_inventory` (`supported` | `denied` |
    `incomplete_or_changing` | `unavailable`), `listener_table` (`supported` |
    `denied` | `incomplete_or_changing` | `unavailable`), and sandbox
    `guidance` when a permission denial is observed.
  - Non-blocking Unix socket connect probe and directory metadata checks
    separate sandbox filesystem/socket permission denials from missing or
    refused sockets without creating or mutating files.
  - Diagnostic-only: never changes `exit_code`, `daemon_disposition`, or
    `generation.ownership`.
- **Immediate inbox wait replacement wake**:
  - `wait --inbox --replace-wait <wait-id>` wakes an idle receiver immediately
    rather than waiting for a new message or the prior deadline.
- **Stop inspection prerequisite diagnostics**:
  - `daemon stop` names the unavailable process-inspection stage without
    echoing process arguments or executable paths, and `daemon ownable`
    clarifies that remote bot-identity matching does not grant native stop or
    restart authority.
- **Dependency and policy updates**:
  - Refreshed `tokio` to `1.54.1` for `RUSTSEC-2026-0386` and enabled full
    retained-graph (`include-dev = true`) license checks and `3leaps/waitprims`
    source allowlisting in `deny.toml`.

## Upgrade Notes

Installing the v0.3.4 binary does not automatically replace already-running
daemons. Stop or finish your active waits first: when targeting a pre-v0.3.4
daemon that has no v1 runtime record on disk, the first `daemon restart` (or
`daemon stop`) from v0.3.3 uses the verified legacy stop fallback, which does
not refuse with `Busy` and terminates active waits before starting the v1
managed successor. Once running on a v1-managed daemon, subsequent
`daemon restart` and `daemon stop` calls enforce the `Busy` active-obligation
guard and `Exited` tombstone contract.

If `chanvoy doctor` in a sandboxed agent session reports
`native_runtime.socket_access.status = "denied"` or `process_inventory` /
`listener_table` as `"denied"`, follow the emitted `guidance` (set
`CHANVOY_RUNTIME_DIR` to a mutually writable 0700 directory or update the host
sandbox profile allowlist).

This cut ships signed GitHub Release binaries only, without crates.io
publication.
