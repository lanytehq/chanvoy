# Release Notes — v0.3.0

**Release Date**: unreleased
**Status**: Private package on current `main`. Fingerprints are
inserted by `decernor` 0.1.4+; this cut is not a public launch.

## Summary

v0.3.0 makes a cited post reachable. Several verbs already took a post
id — resuming after one, replying to one, reacting to one — but none of
them would *show* you it. The one read verb that accepted an id was the
resume flag, which is defined to exclude the post it names, so a
citation without a searchable phrase in it could not be reopened at
all. Two verbs close that: `show` fetches one post, and `thread`
fetches the conversation it belongs to.

It also repairs two long-standing integrity problems in reading. Every
message was attributed to `unknown`, because posts carry only a user id
and the code read an author-name field the server does not send on a
post. And thread reads filtered posts through that same absent field,
so they discarded every post and reported success with nothing in them
— a silent failure that looked exactly like an empty thread.

This is a **minor-version boundary rather than a patch**, taken
deliberately. See *Compatibility* below.

## What changed for people using chanvoy

- **`chanvoy show <channel> <post-id>`** — reopen a cited post.
- **`chanvoy thread <channel> <root-or-post-id> [--latest]`** — read a
  whole conversation. It accepts **any** post in the thread, not only
  the first one, so a citation is usable without first working out
  which ids are roots.
- **Real author names.** When a name genuinely cannot be resolved the
  author is reported as the literal user id — something an operator can
  look up — rather than a placeholder that reads like a person.
- **Threads come back.** A conversation with a root and N replies
  returns N+1 messages.
- **Every message names the thread it belongs to**, and default `read`
  output now carries `id=` on each row so a post id can be handed
  straight to another command without re-running with `--json`.
- **Reads are scoped to the channel you named.** A post is proven to
  belong to that channel before any of it is returned, and that now
  covers the gateway's thread reads, which previously trusted the
  caller's channel entirely.
- **Truncated reads say so**, instead of being indistinguishable from
  complete ones.
- **Wait, MCP, waitprims.** `chanvoy wait` holds on waitprims
  (`wait_channel_v3` / fan-in `wait_channels_v1`, poll
  `run_poll_cycle`). Waitprims is pinned to git tag `v0.1.2`.
  `chanvoy mcp` is an access face on the profile daemon. `wait --follow`
  is not in this cut.
- **Release-signing fingerprints** come from `decernor fingerprint`
  on exported public files (`--gpg-role primary`; minisign public-blob
  SHA-256). `keys/expected-fingerprints.txt` stays TBD until both
  publics exist and the inserter writes both lines. No crates.io
  or public first-adopter claim.

## Compatibility

**This release is a source-breaking boundary for code that builds
against `chanvoy-core`.**

What does **not** need migrating: there is no on-disk or state
migration, exit codes are unchanged, and a binary distribution needs no
source rebuild.

What operators should check:

- **Restart the daemon.** A newly installed command talking to a daemon
  that is still running the previous version cannot use the new verbs;
  it will tell you so and name the fix, but the restart is required.
- **Strict parsers of human output.** Default `read` rows now carry an
  `id=` crumb, and a `root=` crumb where a thread root is known. Anything
  matching those lines exactly should be reviewed.
- **Strict parsers of stderr.** Errors print their message rather than an
  internal shape, so text that scripts matched on has changed.
- **JSON consumers** gain a `root_id` field on every message. Existing
  fields are unchanged, so this is additive.

For Rust callers:

- `CoreError` is now `#[non_exhaustive]`. Code matching on it needs a
  catch-all arm (`_ => { ... }`). This is the point of the change:
  after this boundary, further **variants** added to that type stop
  being breaking, and it is a taxonomy that will keep growing. (It does
  not make every conceivable change to the type safe — adding fields to
  an existing variant, for instance, is a separate question.)
- Two error cases were added — a thread request that returns no posts,
  and the removed unbound thread read.
- `MattermostClient::read_thread` is **deprecated and always refuses**.
  Use `read_thread_in_channel(expected_channel_id, channel_name,
  root_post_id)`. The old entry point is kept so existing calls still
  compile, but it cannot be forwarded: doing so would require inventing
  a channel, which is precisely the unscoped read it was removed for.

Adding a variant to an exhaustive public enum is source-breaking in
Rust even though nothing was removed. Earlier guidance in
`docs/architecture.md` said "adding fields is fine", which was too
broad; it has been corrected alongside this release.
