# Release Notes — v0.3.2

**Release Date**: unreleased
**Status**: In preparation for public GitHub binary release

## Summary

v0.3.2 adds wait filters for direct messages and mentions, and optional
burst coalescing on held follow.

Operators can sit on one DM peer (`--dm`), on any DM to this bot
(`--inbox`), or only on posts that mention this bot (`--mention`). Inbox
`--after` is an opaque cursor, not a Mattermost post id.

`--follow --coalesce` is **off unless you pass it**. Five seconds is
recommended; ten seconds is the hard maximum (32 messages). Each burst
is one JSONL line; `tip` is the last message id in that record.

The cut also pins rsfulmen 0.2.0 for file-backed JSON Schema checks of
wait parameters.

## What's New

- `wait --dm <username>` sits on one peer conversation. `--after` is a
  post id on that DM.
- `wait --inbox` sits on any direct message to this bot. `--after` is an
  `inv1.` inbox cursor. `--inbox --follow --coalesce` resumes from
  `next_inbox_cursor` (same cursor shape, not a post id). Do not mix
  `--inbox` with `--dm` on the same profile.
- `wait --mention` completes only on this bot's `@username` token
  (ASCII case-insensitive). `@bot-suffix` is not a match. It is logical
  AND with `--contains` and `--pattern`.
- `--follow --coalesce <duration>` batches matching follow records into
  one JSONL line (default off; recommended 5s; hard max 10s / 32).
  Omission stays one-message-per-line. `armed` is immediate; a pending
  burst flushes before a terminal record.
- File-backed wait-params schema validation via rsfulmen 0.2.0.

Guides: [`docs/guides/wait-follow.md`](../guides/wait-follow.md),
[`docs/guides/wait-dm.md`](../guides/wait-dm.md).

## Upgrade Notes

`make install` updates the CLI and no longer restarts running daemons. It
reports installed-path daemon candidates and leaves them untouched. The legacy
`make install-restart-daemons` target is a reporting-only alias; standalone use
requires `CHANVOY_INSTALL_QUALIFIED_ARTIFACT` to name an independent, designated
artifact whose bytes match the installed CLI. This comparison does not confer
release qualification or prove a daemon's identity or liveness. The artifact is
comparison input only; manual commands use the byte-verified installed path,
not a separate artifact/worktree copy. Revalidate the installed binary before
action so its executable path can satisfy the candidate ownership guard.

Migrate each daemon manually under its owning identity using the qualified
installed binary and explicit profile. Confirm predecessor ownership before
stopping;
independently confirm that same candidate's whole-process death and guarded
runtime cleanup before starting a successor. Stop exit 0, missing PID/socket,
listener absence and refused connection are insufficient. Unknown evidence
withholds startup. Then verify the explicit-profile dual pin and observation
readiness before relying on new wait capabilities. See the
[operator guide](../operator-guide.md#installation-and-daemon-migration).

`--inbox --after` refuses a Mattermost post id. Drain an inbox wait
once, then reuse the returned cursor.

This cut will ship signed GitHub Release binaries only, without crates.io
publication.

For hosts that wake an agent from streamed process output,
`--follow-stdout` wakes once per JSONL line. Pass `--coalesce 5s` when
one wake per burst is wanted. Hosts that wake only when a process exits
should use bounded one-shot `wait`, including `wait --mention`.

## Release provenance compatibility

This cut adopts read-only artifact CI and separate maintainer draft/sign/upload/
promotion steps. See the [release checklist](../../RELEASE_CHECKLIST.md) and
[verification guidance](../security/release-verification.md). SHA256SUMS and
SHA512SUMS plus both detached signature formats are additive. The legacy
checksums.txt, checksums.txt.asc, per-binary .minisig, chanvoy.pub and
chanvoy.gpg.asc names and existing single-platform commands remain available.
Legacy names are deprecated for a future cut; removal requires a later notice.
Public identity approval and re-derivation must be completed before this tag;
this tooling change does not assert a new fingerprint or signing identity.
