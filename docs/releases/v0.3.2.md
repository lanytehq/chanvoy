# Release Notes — v0.3.2

**Release Date**: 2026-09-12
**Status**: Public GitHub binary release

## Summary

v0.3.2 adds wait filters for direct messages and mentions, and optional
burst coalescing on held follow.

Operators can sit on one DM peer (`--dm`), on any DM to this bot
(`--inbox`), or only on posts that mention this bot (`--mention`). Inbox
`--after` is an opaque cursor, not a Mattermost post id.

`--follow --coalesce` is **off unless you pass it**. Five seconds is
recommended; ten seconds is the hard maximum (32 messages). Each burst
is one JSONL line; `tip` is the last message id in that record.

The cut also pins rsfulmen 0.2.0 for file-backed JSON Schema checks of
wait parameters.

## What's New

- `wait --dm <username>` sits on one peer conversation. `--after` is a
  post id on that DM.
- `wait --inbox` sits on any direct message to this bot. `--after` is an
  `inv1.` inbox cursor. Do not mix `--inbox` with `--dm` on the same
  profile.
- `wait --mention` completes only on this bot's `@username` token
  (ASCII case-insensitive). `@bot-suffix` is not a match. It is logical
  AND with `--contains` and `--pattern`.
- `--follow --coalesce <duration>` batches matching follow records into
  one JSONL line (default off; recommended 5s; hard max 10s / 32).
  Omission stays one-message-per-line. `armed` is immediate; a pending
  burst flushes before a terminal record.
- File-backed wait-params schema validation via rsfulmen 0.2.0.

Guides: [`docs/guides/wait-follow.md`](../guides/wait-follow.md),
[`docs/guides/wait-dm.md`](../guides/wait-dm.md).

## Upgrade Notes

Restart the profile daemon after installing the new binary so the CLI
and daemon agree on `--dm`, `--inbox`, `--mention`, `--coalesce`, and
follow capabilities.

`--inbox --after` refuses a Mattermost post id. Drain an inbox wait
once, then reuse the returned cursor.

This cut ships signed GitHub Release binaries only. It is not on
crates.io.

For hosts that wake an agent from streamed process output,
`--follow-stdout` wakes once per JSONL line. Pass `--coalesce 5s` when
one wake per burst is wanted. Hosts that wake only when a process exits
should use bounded one-shot `wait`, including `wait --mention`.
