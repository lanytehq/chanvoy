# Release Notes — v0.3.3

**Release Date**: 2026-10-23
**Status**: In preparation for public GitHub binary release

## Summary

v0.3.3 makes daemon stop, setup and refresh safer around the daemon's
runtime state.

The daemon pid file no longer lives in the OS temp directory when no runtime
directory is configured, so temp cleanup cannot remove it from a running
daemon. `daemon stop`, `auto-setup` and profile refresh can now stop a live
daemon whose pid file is missing, using the socket's kernel peer process and
the same identity checks as before. The force signal is bound to the verified
process on Linux; macOS keeps a documented residual.

`auto-setup` now exits **6** when it would reuse a daemon of a different or
unverifiable build generation, instead of reporting success.

The daemon also answers the two versioned runtime-control methods,
`runtime_retire_v1` and `runtime_observation_v1`, through strict schema
decoding with bounded input. They are inactive: retirement is always refused
until native lifecycle binding lands, and observation reports only the
daemon's application state. Existing methods and clients are unaffected.

## What's New

- Durable pid file under `<config root>/run/<key>/` when no runtime directory
  is configured. The socket location is unchanged; `CHANVOY_RUNTIME_DIR` still
  places both.
- Pid-less stop: the socket's kernel peer PID stands in for a missing pid file
  in `daemon stop`, `auto-setup` and refresh. A socket with no live listener
  and no pid file is still retained.
- Stale pid records from before the current boot, or older than the process now
  holding that PID, are released without signalling that process.
- `daemon stop` sends shutdown on the connection whose peer it validated. On
  Linux the force signal goes through a pidfd bound to the captured process.
- `auto-setup` exits 6 on a mismatched or unverifiable daemon generation and
  keeps the existing daemon, profile and state. Setup JSON reports both build
  identities and the generation decision.
- Human-readable `daemon status` shows `daemon_version` from the responding
  daemon.
- Daemon shutdown collects client, websocket, startup and IPC tasks before
  runtime cleanup.
- `runtime_retire_v1` and `runtime_observation_v1` are routed through strict
  runtime-control v1 decoding: 16 KiB frame cap, duplicate keys refused, at
  most cap + 1 bytes read before classification, and no fallback to legacy
  handlers. Retirement is refused with `native_evidence_unavailable`.

## Dependency and verification updates

- Refresh quinn-proto, rustls, rustls-webpki, webpki-roots and
  webpki-root-certs for RUSTSEC-2026-0338 through 0342, 0346 through 0349,
  0381, 0382 and 0383, and anyhow and rand for RUSTSEC-2026-0190 and 0097.
  The webpki roots update changes the trusted CA set.
- RUSTSEC-2024-0449 (unsafe-libyaml, unmaintained) is recorded as an accepted
  advisory exception.
- The offline SBOM route pins goneat 0.6.6.
- `make check` and `make pr-final` refuse Rust sources that spawn process
  inspection or signalling tools.

## Upgrade Notes

Daemons started by an older CLI are not changed by installing this one. After
upgrading, `auto-setup` against an older running daemon exits **6** and leaves
it in place. Stop it with `chanvoy --profile <name> daemon stop`, then run
`auto-setup` again. A daemon whose pid file was already removed by temp cleanup
can now be stopped the same way.

On macOS, `daemon stop` checks the daemon's registered exit event immediately
before a force signal; a narrow window remains in which a reused PID could
receive it. See the
[operator guide](../operator-guide.md#confirmed-daemon-shutdown).

`chanvoy auto-setup` no longer sets the host-wide `active_profile` marker unless
`--activate` is passed. This shipped in the 0.3.2 binaries and is documented
here. Pin `CHANVOY_PROFILE` or pass `--profile` on shared hosts.

This cut ships signed GitHub Release binaries only, without crates.io
publication.
